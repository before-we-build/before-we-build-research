## Что считать дублем

Совпадение темы недостаточно. Нужны совпадающие входы, результат и полномочия.
Разведены границы concept Q&A / развёрнутое объяснение; естественность / понимание /
доказательность; визуальная концепция / производственная раскадровка; весь
видеопакет / его подписи и сцены; протокол / психометрия / статистика.
В ORGANIZATION.md каждому такому результату назначен один владелец.

Одноимённые short-video agent и skill specification не являются двумя агентами:
первый задаёт владельца работы, второй описывает процедуру. Старые плоские
`.opencode/skills/*.md` не доказывают обнаружение навыка конкретным runtime.

Не найдено оснований объявить конкретного специалиста неиспользуемым или удалить
его только по возрасту файла. Все 53 имени сохранены, роли вызываются по задаче.
Для будущего сокращения нужны реальные случаи дублирующей работы, замещающий
владелец, проверка входящих ссылок и регрессионный пример. Узкие проверяющие
сохраняются, даже если вызываются редко.

## Принятые организационные правила

Один владелец результата; прямой вызов подходящего эксперта; координатор только
при интеграции разных результатов; отдельный автор и проверяющий; один писатель
на файл; ограниченный handoff с входами, результатом и критерием завершения.
Подчинение описывает ответственность, а не научную или исполнительную власть.
Новая роль требует доказанного пробела. Эти правила — решение для BWB, а не
универсальная норма о необходимом количестве агентов.

## Источники и ограничения

[Официальная документация OpenCode об агентах](https://opencode.ai/docs/agents/)
описывает primary/subagent и назначение через description. Это основание для
явных режимов, а не доказательство качества нашей маршрутизации.
[Документация разрешений V2](https://opencode.ai/v2/docs/permissions) использует
иную схему разрешений, чем примеры неверсионированной страницы. Поэтому
существующие boolean permissions не мигрировались вслепую.

OpenCode CLI отсутствует в этой среде. Не проверены эффективные разрешения,
доступность моделей, глобальные агенты, реальная частота вызовов и внешние
расписания. Статическая проверка не доказывает least privilege. Модели не менялись.
Для runtime-приёмки нужны установленная версия OpenCode, фактический agent list,
проверка effective permissions и пробные маршруты: одна типология, эмпирический
протокол, wiki-правка с review, короткое видео. Любые внешние действия остаются
в пределах пользовательской авторизации.
