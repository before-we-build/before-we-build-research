# Общее ядро агентов и адаптеры — 6 сентября 2026

По явному запросу пользователя выделен общий источник ролей и созданы адаптеры
OpenCode и Codex. Предыдущие изменения организационной структуры сохранены.

## Результат

- `.agents/registry.json`: 53 стабильных идентификатора, описания, команды,
  ответственность, подчинение и намерение read/write; без моделей и vendor-разрешений.
- `.agents/roles/*.md`: 53 канонические инструкции.
- `.agents/ORGANIZATION.md`: общий порядок работы и генерируемый реестр.
- `.agents/adapters/*.json`: настройки конкретных движков.
- `.opencode/agents/*.md`: 53 генерируемых адаптера, один primary.
- `.codex/agents/*.toml`: 52 генерируемых подагента; роль master выполняет основной
  диалог через корневой AGENTS.md, без создания второго координатора.
- `.codex/config.toml`: три одновременных дочерних потока; без изменения модели,
  провайдера, учётных данных и режима подтверждений основной сессии.

## Перенос и границы

Нормализованные тела всех 53 инструкций совпали с исходными по SHA-256.
Нормализация только убирает повторявшийся организационный пролог и меняет пути
авторинга `.opencode/agents` / ORGANIZATION на общие `.agents` пути. Контрольные
хеши сохранены в `.agent-learning/reviews/2026-09-06-agent-core-migration-hashes.json`.
Методы трёх Psychosophy-типировщиков сохранены в реестре. Доменные утверждения,
ограничения и роли проверяющих не переписывались.

Модели OpenCode сохранены. Codex наследует модель и reasoning основной сессии,
если для роли явно не записано переопределение в его adapter settings.
OpenCode-адаптер целится в документированный V1-формат `permission`; прежние
неподтверждённые boolean `permissions` и `tool_use` заменены. Для read-ролей
запрещены edit и bash; для write разрешён edit, остальные политики наследуются.
Codex использует read-only / workspace-write как настройки sandbox ролей.
Это разные механизмы, а не обещание одинакового исполнения прав во всех средах.
Живые настройки хоста, сеть и внешние инструменты остаются отдельными ограничениями.

V2 OpenCode и другие хосты требуют своих адаптеров. Старые `.opencode/data/`,
`.opencode/skills/` и путь к wiki-audit остаются доступными ресурсами репозитория;
их использование не требует процесса OpenCode. Плоские skill specifications не
объявляются автоматически зарегистрированными навыками Codex.

Активные правила управления, шаблоны и ссылка из SNIL переключены на ядро.
Исторические журналы и исходные материалы сохранены. Сканер wiki-ссылок теперь
учитывает канонические роли вместо дублирующих сгенерированных промптов.

## Автоматизация

`python3 scripts/generate_agent_adapters.py --write` обновляет оба адаптера.
`--check` ничего не пишет и обнаруживает отсутствующие, лишние и изменённые файлы.
Нет автоматического удаления. Неизвестный существующий конфигурационный файл
не перезаписывается обычным --write. Первый перенос использовал явно разрешённый
--adopt-existing. Выходные symlink-пути не перезаписываются.

CI проверяет ядро и адаптеры; agent linter тоже вызывает эту проверку.
Тесты проверяют циклы, потерянные роли, повторные JSON-ключи, перенос изменений
в оба движка, экранирование TOML, наследование моделей, отсутствие лишнего
координатора, различия read/write и защиту чужих файлов.
