# Проверка архитектуры перед коммитом — 6 сентября 2026

Вывод: устройство общего ядра и двух адаптеров соответствует перечисленным ниже
инженерным принципам и пригодно для включения в репозиторий после прохождения CI.
Это оценка проекта, а не сертификация всех 53 промптов или доказательство их
эффективности на любой модели.

## Сопоставление с первоисточниками

| Рекомендация | Реализация и предел проверки |
|---|---|
| Добавлять агентную сложность только по необходимости; различать маршрутизацию, независимые задачи и координацию | Роли вызываются по задаче; один владелец результата, прямой маршрут к узкому специалисту, три уровня и ограниченная параллельность |
| Разделять стабильные интерфейсы и меняющиеся реализации | Общие роли и реестр отделены от модели, разрешений и формата конкретного хоста; это применение принципа разделения, не реализация Managed Agents |
| Проверять работу по наблюдаемым результатам | Регрессионные тесты, CI, воспроизводимая генерация и отчёты; качество реальных модельных ответов пока не измерено |
| Использовать нативные форматы custom agents | Codex TOML и OpenCode V1 Markdown, с явно указанными границами совместимости |
| Ограничивать параллельные правки | Один писатель на артефакт; проверяющий возвращает замечания, а не конкурирующую правку |

Источники: [Anthropic — Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)
(2024; страница предупреждает об изменении инструментов, использована для
организационных принципов), [Anthropic — Scaling Managed Agents](https://www.anthropic.com/engineering/managed-agents)
(2026; разделение интерфейсов), [OpenAI — Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents),
[OpenCode — Agents](https://opencode.ai/docs/agents/). Страницы открыты 2026-09-06.

## Найденное и исправленное

Независимый read-only агент adapter_review проверил генератор, реестр, адаптеры,
тесты и границы ролей. Он подтвердил отсутствие доказанного блокирующего дефекта
генерации, но выявил несоответствие read-прав и требований сохранять результаты.
Wiki-проверяющий теперь возвращает текст отчёта и рекомендуемые пути владельцу;
проектировщик данных возвращает план реализации. Запись данных ему не добавлена.
Убраны обязательные shell-примеры проверяющего и фиксированный порог старых дат.

Основной агент дополнительно исправил отклонение JSON-контейнеров неверного типа
и разбор frontmatter с тремя дефисами внутри поля. Добавлены регрессионные тесты.

## Что не установлено

Нет измерений, показывающих, что именно 53 роли оптимальны по качеству, цене и
задержке. Сохранение ролей с вызовом по задаче не заменяет таких измерений.
OpenCode недоступен в текущей оболочке; Codex загрузил конфигурацию, но полный
цикл вызова каждой роли не проверялся. Эти пределы явно записаны в документации.
Они не скрываются за успешными структурными тестами.

## Проверка и отправка

Remote — GitHub `before-we-build/before-we-build-research`; GitLab remote и
.gitlab-ci.yml отсутствуют. Под пользовательским запросом проверки пайплайна
проверяется фактически настроенный GitHub Actions workflow Wiki quality.
Несвязанный ранее существовавший reports/archive/ исключается из коммита.
Локально прошли все 110 unittest-тестов, строгие проверки wiki, section IDs,
ссылок и утверждений, сверка индекса и инвентаря, проверка адаптеров и agent linter,
проверки читаемости и git diff --check. Независимое повторное ревью не выявило
оставшегося блокирующего дефекта. URL удалённого запуска и его результат
сообщаются пользователю после push.
