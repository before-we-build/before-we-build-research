# Agent organization

Canonical source: `.agents/registry.json` and `.agents/roles/*.md`.
This document governs all runtime adapters. The roster is generated by
`python3 scripts/generate_agent_adapters.py --write`. Last reviewed: 2026-09-06.

## Ownership and delegation

- `master-orchestrator` is the main-session role and owns the user-facing result.
- Choose one deliverable owner. Route a bounded question directly to its specialist;
  use a coordinator when several distinct specialist outputs need integration.
- `typology-researcher` coordinates cross-system source doctrine;
  `research-orchestrator` coordinates empirical study pipelines. They are peer
  coordinators, not a mandatory chain. `typing-lead` coordinates individual
  provisional type hypotheses; it does not validate measurement instruments.
- Reporting metadata expresses organizational accountability, not an execution
  permission or a requirement to traverse every parent. Keep call paths to at
  most root → coordinator → specialist. At that depth, return requests for other
  expertise to the task owner instead of recursively launching another team.
- Each handoff states objective, input evidence, output artifact, acceptance
  criteria, permitted files, existing authorization and a stopping condition.
  Return findings, sources, uncertainty and unresolved blockers to the owner.
- Parallel tasks must be independent and have disjoint write targets. Assign one
  writer per artifact; reviewers return findings rather than competing rewrites.
- Delegate specialist judgment first. Routine clerical work and final synthesis
  do not require an extra agent. Do not run the whole roster for ordinary tasks.
- When the host cannot invoke a named role, disclose that limitation. Reading a
  role prompt is not an independent specialist review.

## Boundaries for overlapping roles

| Task / output | Owner | Boundary / handoff |
|---|---|---|
| Cross-system source comparison | typology-researcher | Select system experts; empirical research pipeline belongs to research-orchestrator |
| Study protocol and outcomes | experiment-designer | Statistics to statistical-validation-agent; construct/item validity to psychometrics-methodologist |
| Instrument audit packet | typology-test-evaluation-expert | Coordinates a bounded audit; does not replace psychometrics, statistics or domain reviewers |
| Future compatibility measurement prerequisites | compatibility-measurement-researcher | No current score; studies go to research-orchestrator |
| Individual provisional Psychosophy hypothesis | typing-lead | Quick self-ranking, existing test output and interview are distinct evidence paths; do not run all three automatically |
| Wiki content changes | wiki-contributor | wiki-consistency-checker owns review findings, not a second competing edit |
| Source tracing | source-provenance-auditor | Empirical warrant to empirical-claims-caveats-reviewer; publication rights to copyright-licensing-reviewer |
| Short concept Q&A | type-explain | before-we-build-plain-language-translator owns longer explanations or rewrites |
| Explanation / rewrite | before-we-build-plain-language-translator | Story/analogy to before-we-build-storyteller; skeptical-audience framing to before-we-build-skeptic-bridge |
| Prose naturalness findings | naturalness-style-reviewer | vanka-the-layman checks comprehension; empirical-claims-caveats-reviewer checks warrant |
| Visual concept / explanatory diagram | visual-explainer | Timed scenes from an approved script belong to visual-storyboard-agent |
| Talk / slide narrative | before-we-build-presentation-designer | UI implementation belongs to responsive-ui-design-systems-expert |
| Complete short-video package | short-video-package-builder | Owns assembly of one package; captions to social-caption-hashtag-agent and scenes to visual-storyboard-agent when needed; do not generate duplicate final packages |
| Campaign strategy | social-media-strategy-agent | publication-planner-agent owns calendar/approval packet, not strategy or permission to publish |
| Public marketing claims review | marketing-claims-safety-reviewer | Empirical warrant remains with empirical-claims-caveats-reviewer; neither is a source of empirical evidence |
| Theology across traditions | christian-theology-researcher | Baptist pastoral/audience framing belongs to baptist-pastor; no scientific validation authority |
| Military role requirements | military-roles-researcher | military-specialty-advisor owns evidence-first preparation comparison; no typological selection |
| Agent instruction changes | agent-improvement-steward | Learning log → proposal → relevant review → authorized patch → verification |

All specialist roles are **on demand**. Their presence is not a standing job or
an instruction to run them on every task. Career, military, pastoral, finance,
marketing and production roles require a matching user task. Domain reviewers
remain available whenever a relevant claim needs review.

## Lifecycle

Keep an agent when it needs a distinct judgment, context or review boundary.
Use a workflow/skill specification for a repeatable procedure within an owner's
job. The same-named short-video agent and the legacy `.opencode/skills/short-video-package-builder.md`
are an owner plus a procedure specification, not two runtime agents. Flat skill
specifications are not evidence that a host discovered or executed a skill.

No role is retired based on file age or absent mentions alone. Before merging
or archiving a role, record representative tasks, observed duplicate output,
its replacement owner, all inbound protocol/skill references and a regression
exercise. Preserve substantive reviewer independence and the learning loop.
No new agent without a demonstrated gap and a distinct output contract.

For future task retrospectives record task category, selected roles, duplicated
work, useful outputs and failed handoffs without personal/sensitive content.
Review those records after representative use; do not fabricate invocation counts.

## Runtime adaptation

Role accountability is independent of runtime execution controls. `reports_to`
does not grant permissions or force nested calls. Read `.agents/README.md` for
adapter formats, model inheritance, permission limitations and verification.
Legacy `.opencode/data/` and `.opencode/skills/` paths are shared repository
resources; reading them does not require OpenCode or imply skill registration.
